# 消融实验

2026-09-22 的历史实验基于业务源码 `22c9b40c97ca441ad447025904f24c3afe4b280c`。Windows 与 Debian WSL2 的 4 个基线和 16 个单因素变体结果一致；完整计数、失败用例与源码哈希保存在 [ablation-results.json](ablation-results.json)。项目架构见 [README](../../../README.zh-CN.md)。

## 方法与边界

每个变体在独立 Vitest 进程中运行，通过 Vite 临时替换一个业务机制。工具校验替换锚点、基线成功、测试数量和业务源码哈希，结果保存在 `coverage/ablation/<UTC 时间>/`。测试断言不随变体改变。

测试使用固定负载、HTTP 注入、Provider 替身和 jsdom，衡量功能与资源契约，不测真实音质、微软吞吐量或浏览器解码延迟。失败用例数反映当前测试的敏感度，不表示线上故障率或模块重要性。

## 历史结果

基线：service 160、Provider 29、HTTP 21、播放 17 个测试全部通过。16 个变体中，15 个触发断言失败，1 个存活。去掉活跃上限的变体另产生一个未处理错误，未计作普通断言失败。

| 单项消融                              | 失败/同组总数 | 观测与结论                                                                    |
| ------------------------------------- | ------------- | ----------------------------------------------------------------------------- |
| 去掉 TTL 命中                         | 7/160         | 100 次顺序读取，上游调用从 1 增至 100；保留缓存                               |
| 去掉 in-flight 合并                   | 4/160         | 20 个并发冷读取，上游调用从 1 增至 20；保留合并                               |
| 去掉刷新失败时旧值回退                | 3/160         | 故障期间 20 次读取成功数从 20 降到 19；其余请求仍被独立保留的退避分支返回旧值 |
| 去掉错误退避                          | 3/160         | 相同窗口内 20 次故障期读取，失败刷新尝试从 1 增至 20；保留退避                |
| 去掉缓存副本                          | 2/160         | 调用方/上游的对象修改污染缓存；保留隔离                                       |

## 问题处理

| 发现                                        | 当前处理                                                                   |
| ------------------------------------------- | -------------------------------------------------------------------------- |
| 手动限流 hook 的 `groupId` 没有参与配额计算 | 已删除。两条路由仍复用同一个 hook/store 和固定 key，保持共享预算           |
| 原进度测试不能区分逐块报告与 32 KiB 节流    | 已保留大块场景并增加 1 KiB 小块输入，断言回调恰好 3 次；取消节流时为 65 次 |
| Linux 断连测试清理超时                      | 已在业务断言后关闭测试客户端连接，保留取消与队列恢复断言                   |
| i18n 测试出现异步更新警告                   | 已等待重挂载和存储异常场景的异步初始化                                     |
| CRLF checkout 影响补丁与格式检查            | 仓库通过 `.gitattributes` 统一文本为 LF                                    |

缓存、并发上限、排队边界、共享配额、分段许可、迟到连接回收和 Blob 回退均有回归证据支持保留。实验没有证明 300 码点、4/16 容量或缓存期限已经最优，参数调整需要独立的真实负载测量。
