# 設定リファレンスマニュアル

このドキュメントでは、`edgeTTS` の全環境変数設定、認証仕様、並行処理キュー制御、およびコンテナセキュリティ基準について詳細を記載します。

---

## 環境変数リファレンス

### アプリケーションサーバー設定

以下の環境変数は Fastify アプリケーションサーバー（`apps/server`）で読み込まれます：

| 変数名                        | 説明                                    | 設定可能値                          | デフォルト値                                         |
| :---------------------------- | :-------------------------------------- | :---------------------------------- | :--------------------------------------------------- |
| `HOST`                        | HTTP サーバーがバインドする IP アドレス | 有効な IPv4 / IPv6 アドレス         | `127.0.0.1` (ベアメタル Node)<br>`0.0.0.0` (Docker)  |
| `PORT`                        | HTTP 待受ポート                         | `1`–`65535`                         | `8080`                                               |
| `NODE_ENV`                    | 実行環境モード                          | `production`, `development`, `test` | `production` (Docker)                                |
| `API_KEY`                     | Bearer 認証用シークレットキー           | 16 文字以上の文字列（空白不可）     | なし                                                 |
| `REQUIRE_API_KEY`             | API キー認証の強制有効化                | `true` または `false`               | `false` (ベアメタル Node)<br>`true` (Docker Compose) |
| `SPEECH_RATE_LIMIT_MAX`       | 時間枠内の最大リクエスト許容量          | 整数（`1`–`10000`）                 | `12`                                                 |
| `SPEECH_RATE_LIMIT_WINDOW_MS` | レート制限スライディング枠（ミリ秒）    | 整数（`100`–`3600000`）             | `10000`（10 秒）                                     |
| `SERVE_STATIC`                | WebUI 静的アセット配信の有効化          | `true` または `false`               | `production` で自動有効                              |
| `WEB_DIST_DIR`                | フロントエンド成果物ディレクトリパス    | 絶対パスまたは相対パス              | `/app/web-dist` (Docker)<br>`apps/web/dist` (Node)   |

### Docker Compose ホスト変数（`.env`）

`compose.yaml` でホスト側のポート転送を設定するための変数です：

| 変数名                 | 説明                                | デフォルト値 |
| :--------------------- | :---------------------------------- | :----------- |
| `EDGETTS_BIND_ADDRESS` | コンテナポートを転送するホスト側 IP | `127.0.0.1`  |
| `EDGETTS_HOST_PORT`    | ホスト側で公開するポート番号        | `8080`       |

## 認証とセキュリティ仕様

### Bearer トークン仕様

認証が有効な場合（`REQUIRE_API_KEY=true`）、保護されたエンドポイントへのリクエストには HTTP `Authorization` ヘッダーが必要です：

```http
Authorization: Bearer <API_KEY>
```

- **保護対象ルート**: `GET /api/voices`、`POST /api/speech`、`POST /v1/audio/speech`。
- **公開ルート**: `GET /health`、`GET /api/health`、および Web ワークベンチ静的ファイル（`GET /`）。

### セキュリティ設計

1. **クエリパラメータによるキー送信の非推奨化**: URL クエリパラメータ（例: `?api_key=`）によるキーの受け入れは意図的に**サポートしていません**。URL はプロキシのアクセスログ、ブラウザ履歴、Referer 等で漏洩するリスクが高いためです。
2. **定数時間比較**: タイミング攻撃（Timing Attack）を防ぐため、キーの検証には `crypto.timingSafeEqual` とハッシュ計算を使用しています。
3. **最小長要件**: キーは空白を含まない 16 文字以上である必要があります。
4. **揮発性ブラウザメモリ保持**: Web ワークベンチに入力したキーは React の揮発性ステート内にのみ保持され、`localStorage`、Cookie、URL に保存されることはありません。

## 並行制御とキュー管理

`edgeTTS` はメモリ上で動作する公正な並行制御機構（`TtsService`）を備えています：

```text
リクエスト受信
    │
    ▼
レートリミッター (プロセスあたり 12 回 / 10秒)
    │
    ▼
並行制御リミッター (TtsService Concurrency Limiter)
    │
    ├─ 実行中ストリーム < 4  ──► アップストリームへ接続し合成開始
    │
    ├─ 実行中ストリーム = 4  ──► FIFO 待機キューへ格納 (最大 16 スロット)
    │
    └─ キュー満杯 (16)       ──► 503 応答 (SERVER_BUSY)
```

- **長文ストリームの公平性維持**: 長文分割合成は、一連のストリーミング全体で 1 つの実行許可を保持します。これにより、分割合成の途中で別のリクエストに割り込まれて再生が途切れるのを防止します。
- **クライアント切断時の即時回収**: クライアントが通信を切断または中止した場合、アップストリーム（Microsoft）の WebSocket セッションを即座に破棄し、並行スロットを解放します。

## レート制限

音声合成ルート（`/api/speech` および `/v1/audio/speech`）はスライディングウィンドウ型レートリミッターで保護されています：

- **標準制限**: 1 プロセスあたり 10 秒間に最大 12 リクエスト。
- **レスポンスヘッダー**:
  - `X-RateLimit-Limit`: ウィンドウ内の最大リクエスト許容量。
  - `X-RateLimit-Remaining`: 残りの利用可能リクエスト数。
  - `X-RateLimit-Reset`: 制限枠がリセットされるまでの秒数。
- **上限超過時**: HTTP 429 エラーと JSON が返却されます：
  ```json
  {
    "error": {
      "code": "RATE_LIMITED",
      "message": "Too many speech requests, please try again later"
    }
  }
  ```

## 音色キャッシュ

- `GET /api/voices` で取得した音色リストは、サーバーメモリ上に **6 時間** キャッシュされます。
- アップストリームのエラー発生時は 5 秒間のバックオフを適用し、リクエスト過多を防ぎます。

## コンテナセキュリティ基準

公式 Docker イメージは最小権限の原則に厳格に準拠しています：

- **非 root ユーザー実行**: 非特権ユーザー `node`（`UID 1000: GID 1000`）で動作。
- **読み取り専用ルート**: ルートファイルシステムは完全に読み取り専用（`--read-only`）。
- **ケーパビリティ全破棄**: 全ての Linux ケーパビリティを破棄（`--cap-drop=ALL`）。
- **特権昇格防止**: `no-new-privileges:true` を適用。
- **一時領域の制限**: 書き込み可能な一時領域は `/tmp`（`tmpfs`）のみ。
- **シグナルとゾンビ回収**: `tini`（`--init`）を 1 番プロセスとして使用し、30 秒の停止猶予（`stop_grace_period: 30s`）を付与。
