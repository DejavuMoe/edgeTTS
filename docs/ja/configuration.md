# 設定リファレンスマニュアル

このドキュメントでは、`edgeTTS` の全環境変数設定、認証仕様、並行処理キュー制御、およびコンテナセキュリティ基準について詳細を記載します。

`REQUIRE_API_KEY` はキー未設定時に起動を拒否するかを制御し、設定済みキーの認証を無効にしません。外部認証を使う場合は `REQUIRE_API_KEY=false` と `API_KEY` の未設定が必要です。production ではキー必須、ローカル開発では任意です。Node は `.env` を自動読込しません。環境変数、`node --env-file=...`、または systemd の `EnvironmentFile` を使います。Compose が渡すのは `environment` に列挙した変数のみです。

起動時にすべての変数を一括検証し、不正な値があれば問題をすべて列挙して終了します。認識できない値はエラーとなり、既定値へ暗黙にフォールバックすることはありません。未設定の変数は下表の既定値を使います。

## 環境変数リファレンス

### アプリケーションサーバー設定

以下の環境変数は Fastify アプリケーションサーバー（`apps/server`）で読み込まれます：

| 変数名                        | 説明                                                | 設定可能値                                                               | デフォルト値                                        |
| :---------------------------- | :-------------------------------------------------- | :----------------------------------------------------------------------- | :-------------------------------------------------- |
| `HOST`                        | HTTP サーバーがバインドする IP アドレス             | 有効な IPv4 / IPv6 アドレス                                              | `127.0.0.1` (ベアメタル Node)<br>`0.0.0.0` (Docker) |
| `PORT`                        | HTTP 待受ポート                                     | `1`–`65535`                                                              | `8080`                                              |
| `NODE_ENV`                    | 実行環境モード                                      | `production`, `development`, `test`                                      | `production` (Docker)                               |
| `API_KEY`                     | Bearer 認証用シークレットキー                       | 16 文字以上の文字列（空白不可）                                          | なし                                                |
| `REQUIRE_API_KEY`             | 起動時にキー設定を必須にする                        | `true` または `false`                                                    | `true`（production / Compose）、他は `false`        |
| `SPEECH_RATE_LIMIT_MAX`       | 時間枠内の最大リクエスト許容量                      | 整数（`1`–`10000`）                                                      | `12`                                                |
| `SPEECH_RATE_LIMIT_WINDOW_MS` | レート制限固定時間枠（ミリ秒）                      | 整数（`100`–`3600000`）                                                  | `10000`（10 秒）                                    |
| `SPEECH_RATE_LIMIT_SCOPE`     | 音声の制限枠を共有する範囲                          | `global` または `ip`                                                     | `global`                                            |
| `SERVE_STATIC`                | WebUI 静的アセット配信の有効化                      | `true` または `false`                                                    | `production` で自動有効                             |
| `WEB_DIST_DIR`                | フロントエンド成果物ディレクトリパス                | 絶対パスまたは相対パス                                                   | `/app/web-dist` (Docker)<br>`apps/web/dist` (Node)  |
| `TRUST_PROXY`                 | クライアントアドレスを信頼するリバースプロキシ      | `false`、`true`、ホップ数（`1`–`16`）、またはカンマ区切りのアドレス/CIDR | `false`                                             |
| `METRICS_ENABLED`             | `/api/metrics` で Prometheus メトリクスを提供するか | `true` または `false`                                                    | `false`                                             |

### 容量とタイムアウトの調整

既定値は単一インスタンスのセルフホスト向けです。実際の負荷を計測してから変更してください。

| 変数名                       | 説明                                         | 設定可能値                  | 既定値               |
| :--------------------------- | :------------------------------------------- | :-------------------------- | :------------------- |
| `SYNTHESIS_MAX_CONCURRENT`   | プロセスあたりの実行中合成ストリーム数       | 整数（`1`–`64`）            | `4`                  |
| `SYNTHESIS_MAX_QUEUED`       | `503 SERVER_BUSY` を返すまでの FIFO 待機数   | 整数（`0`–`1024`）          | `16`                 |
| `VOICE_CACHE_TTL_MS`         | 音色リストのキャッシュ有効期間（ミリ秒）     | 整数（`60000`–`604800000`） | `21600000`（6 時間） |
| `EDGE_VOICES_TIMEOUT_MS`     | アップストリーム音色取得のタイムアウト       | 整数（`1000`–`600000`）     | `10000`（10 秒）     |
| `EDGE_SETUP_TIMEOUT_MS`      | アップストリーム合成の接続準備タイムアウト   | 整数（`1000`–`600000`）     | `10000`（10 秒）     |
| `EDGE_AUDIO_IDLE_TIMEOUT_MS` | 次のアップストリーム音声データを待つ最長時間 | 整数（`1000`–`600000`）     | `120000`（2 分）     |

Compose で設定する場合は、サービスの `environment` にこれらの変数を追加してください。

### Docker Compose ホスト変数（`.env`）

`compose.yaml` でホスト側のポート転送を設定するための変数です：

| 変数名                 | 説明                                | デフォルト値 |
| :--------------------- | :---------------------------------- | :----------- |
| `EDGETTS_BIND_ADDRESS` | コンテナポートを転送するホスト側 IP | `127.0.0.1`  |
| `EDGETTS_HOST_PORT`    | ホスト側で公開するポート番号        | `8080`       |

## 認証とセキュリティ仕様

### Bearer トークン仕様

`API_KEY` が設定されている場合、保護されたエンドポイントへのリクエストには HTTP `Authorization` ヘッダーが必要です：

```http
Authorization: Bearer <API_KEY>
```

- **保護対象ルート**: `GET /api/voices`、`POST /api/speech`、`POST /v1/audio/speech`。
- **公開ルート**: `GET /health`、`GET /api/health`、および Web ワークベンチ静的ファイル（`GET /`）。

1. **クエリパラメータによるキー送信の非推奨化**: URL クエリパラメータ（例: `?api_key=`）によるキーの受け入れは意図的に**サポートしていません**。URL はプロキシのアクセスログ、ブラウザ履歴、Referer 等で漏洩するリスクが高いためです。
2. **定数時間比較**: タイミング攻撃（Timing Attack）を防ぐため、キーの検証には `crypto.timingSafeEqual` とハッシュ計算を使用しています。
3. **最小長要件**: キーは空白を含まない 16 文字以上である必要があります。
4. **揮発性ブラウザメモリ保持**: Web ワークベンチに入力したキーは React の揮発性ステート内にのみ保持され、`localStorage`、Cookie、URL に保存されることはありません。

## 並行制御とキュー管理

既定では 1 プロセスあたり実行中 4 ストリーム（`SYNTHESIS_MAX_CONCURRENT`）、FIFO 待機 16 件（`SYNTHESIS_MAX_QUEUED`）。キューが満杯の場合は `503 SERVER_BUSY` です。

`edgeTTS` はメモリ上で動作する公正な並行制御機構（`TtsService`）を備えています：

- **長文ストリームの公平性維持**: 長文分割合成は、一連のストリーミング全体で 1 つの実行許可を保持します。これにより、分割合成の途中で別のリクエストに割り込まれて再生が途切れるのを防止します。
- **クライアント切断時の即時回収**: クライアントが通信を切断または中止した場合、アップストリーム（Microsoft）の WebSocket セッションを即座に破棄し、並行スロットを解放します。
- **アップストリーム接続の再利用**: 1 つのリクエストのすべての分割区間は 1 本のアップストリーム接続を共有し、区間ごとのハンドシェイクを省きます。区間の合間にサービス側が接続を閉じた場合は、接続準備の期限内に再接続します。詳細は[長文合成の性能（中国語）](../development/research/performance.zh-CN.md)を参照してください。

## レート制限

音声合成ルート（`/api/speech` および `/v1/audio/speech`）は固定ウィンドウ型レートリミッターで保護されています：

- **標準制限**: 1 プロセスあたり 10 秒間に最大 12 リクエスト。
- **レスポンスヘッダー**:
  - `X-RateLimit-Limit`: ウィンドウ内の最大リクエスト許容量。
  - `X-RateLimit-Remaining`: 残りの利用可能リクエスト数。
  - `X-RateLimit-Reset`: 制限枠がリセットされるまでの秒数。
- **上限超過時**: HTTP 429 エラーと JSON が返却されます：
  ```json
  {
    "error": {
      "code": "RATE_LIMITED",
      "message": "Too many speech requests"
    }
  }
  ```

合成キューの待機は最大 **30 秒**で、超過時は `503 SERVER_BUSY` を返します。実行許可を得た音声ストリームの長さは制限しません。既定では接続準備は 10 秒（`EDGE_SETUP_TIMEOUT_MS`）、音声データの無通信期間は 120 秒（`EDGE_AUDIO_IDLE_TIMEOUT_MS`）が上限で、合成全体の時間保証ではありません。

既定では、合成の制限枠は両ルートと全クライアントがプロセス単位で共有します。`SPEECH_RATE_LIMIT_SCOPE=ip` を設定すると、クライアントアドレスごとに独立した枠となり、その枠は引き続き両ルートで共有されます。リバースプロキシの背後では `TRUST_PROXY` が必要です。設定しない場合、すべてのクライアントがプロキシのアドレスとして扱われ、同じ枠を共有します。アドレス単位の制限は偶発的な過負荷を抑えるためのもので、アドレスを変更できる悪意あるクライアントは抑止できません。単一キーのサービスであり、テナント分離は提供しません。個別の認証と配分が必要なら信頼できるゲートウェイで実施し、未検証の転送 IP を識別に使わないでください。音色一覧は認証後に **プロセスあたり毎分 60 回**の別枠で制限します。公開ヘルスチェックは対象外です。

## リクエストサイズ

リクエストボディの上限は 256 KiB で、超過時は `413 PAYLOAD_TOO_LARGE` を返します。この上限は最大の正当なネイティブリクエスト（20,000 コードポイント）を、すべてのコードポイントがサロゲートペアとして JSON エスケープされた場合でも収容します。

## 信頼するプロキシ

既定では edgeTTS は `X-Forwarded-*` ヘッダーを無視するため、ログにはプロキシのアドレスがクライアントとして記録されます。`TRUST_PROXY` にプロキシ自身のアドレスを設定すると、転送されたクライアントアドレスとプロトコルを記録します：

- `loopback`：同一ホスト上のプロキシが素の Node プロセスの前段にある場合。
- Docker ネットワークのゲートウェイアドレスまたは CIDR：ホスト上のプロキシがコンテナの前段にある場合。コンテナから見た接続元はゲートウェイです。
- ホップ数を指定すると、その数のプロキシを信頼します。`true` はすべての接続元を信頼するため、プロキシが edgeTTS への唯一の経路である場合に限って使用してください。そうでなければ任意のクライアントが `X-Forwarded-For` を偽装できます。

`TRUST_PROXY` はリクエストのメタデータとログに影響し、`SPEECH_RATE_LIMIT_SCOPE=ip` の場合は音声のレート制限に使うアドレスも決定します。

## メトリクス

`METRICS_ENABLED=true` の場合、`GET /api/metrics` が Prometheus テキスト形式でメトリクスを提供します。認証には他の保護対象ルートと同じ API キーを使います。ラベルにはルートテンプレートと固定の理由のみを含み、URL、音声、リクエスト本文は含みません。カウンターはプロセス再起動時にリセットされます。音声のストリーミング開始後に発生した失敗は、記録済みのステータスを変更しません。

| メトリクス                                                    | 種類    | 意味                                                  |
| :------------------------------------------------------------ | :------ | :---------------------------------------------------- |
| `edgetts_http_responses_total{method,route,status}`           | counter | ルートテンプレート別の HTTP レスポンス数              |
| `edgetts_synthesis_active`                                    | gauge   | 並行許可を保持しているセッション数                    |
| `edgetts_synthesis_queued`                                    | gauge   | 並行許可を待っているリクエスト数                      |
| `edgetts_synthesis_rejected_total{reason}`                    | counter | `queue_full`、`queue_timeout`、または `unknown_voice` |
| `edgetts_voice_catalog_voices`                                | gauge   | キャッシュ済みの音声数。初回取得前は `0`              |
| `edgetts_voice_catalog_age_seconds`                           | gauge   | 音声一覧キャッシュの経過時間。初回取得前は出力しない  |
| `process_resident_memory_bytes`, `process_start_time_seconds` | gauge   | プロセスのメモリと起動時刻                            |

## 音色キャッシュ

- `GET /api/voices` で取得した音色リストは、サーバーメモリ上に 既定で **6 時間**（`VOICE_CACHE_TTL_MS`）キャッシュされます。
- 初回要求時に音色を取得し、並行取得は同じリクエストを共有します。
- 更新に失敗した場合は保存済み一覧を返し、固定 5 秒の再試行待機を適用します。未取得時は古いデータへのフォールバックや待機制御はありません。
- 取得の論理タイムアウトは既定で 10 秒（`EDGE_VOICES_TIMEOUT_MS`）ですが、依存ライブラリの HTTP リクエスト自体は中止できません。

古い一覧には独立した最大有効期間がありません。

キャッシュ済み一覧が TTL 内にある間は、一覧にない音声を指定した音声リクエストは並行枠を使う前に `400 UNKNOWN_VOICE` を返します。照合では大文字と小文字を区別しません。合成時に一覧を取得することはありません。キャッシュが未取得または期限切れの場合、リクエストはそのまま進み、上流サービスが判断します。

## コンテナセキュリティ基準

イメージは `node` ユーザーで実行します。推奨 Compose / `docker run` の指定で読み取り専用ルート、`cap_drop=ALL`、特権昇格禁止、`/tmp` tmpfs、Docker が注入する init（`init: true` / `--init`）を追加します。これらの実行時制約はイメージ自体には組み込まれていません。

サーバーは `nosniff`、Referrer ポリシー、カメラ/マイク/位置情報制限、CSP を返します。CSP は同一オリジンのスクリプト、コントロールに必要なインラインスタイル、`blob:` 音声を許可し、インラインスクリプトや異なるオリジンからの埋め込みを禁止します。HTTPS はリバースプロキシで提供します。
